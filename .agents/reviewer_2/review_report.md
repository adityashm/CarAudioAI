## 3. Adversarial Assessment & Stress Testing

### 3.1 Stress-Testing Assumptions
1. **Extreme Cabin Dimensions / Off-Road Vehicles**:
   - *Scenario*: Deep or wide vehicles such as Mahindra Thar Roxx ($Dist_{SUB} = 230\text{cm}$) or Tata Harrier ($Dist_{SUB} = 235\text{cm}$).
   - *Result*: Algorithm dynamically recomputes $Dist_{max}$ and all relative delays without negative or unbounded values.
2. **Unconnected Rear Speakers / Active 2-Way Setup**:
   - *Scenario*: User selects "No Rear Speakers (Front Active 2-Way)".
   - *Result*: Rear delay and rear target voltages are omitted/set to 0 without dividing by zero or throwing null pointer exceptions.
3. **Subwoofer Enclosure Variations (Sealed vs Ported)**:
   - *Scenario*: Sealed enclosure selected vs custom tuning frequency ($30\text{Hz}$ - $45\text{Hz}$).
   - *Result*: Ported enclosures accurately apply the $F_{\text{tune}} - 7\text{Hz}$ rule; sealed enclosures default safely to 20Hz infrasonic protection.
4. **Dual-Mode Offline Resilience**:
   - *Scenario*: User runs web app in a garage or vehicle without active backend connectivity.
   - *Result*: All services (`tuningService.ts`, `authService.ts`, `paymentService.ts`, `exportService.ts`) provide deterministic local calculations matching backend algorithms with zero UI freezing.
